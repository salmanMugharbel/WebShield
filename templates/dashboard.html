SQLi SQL Injection

When an application builds SQL statements by joining strings with user input, an attacker can type SQL syntax that changes the structure of the query — bypassing logins or reading other data.

"... WHERE username = '" + username + "'"

Prevention: parameterised queries, least-privilege DB accounts, validation.

XSS Cross-Site Scripting

When untrusted data is inserted into a page without encoding, the browser interprets it as HTML/JavaScript and runs the attacker's script with the victim's privileges. Three types: reflected, stored and DOM-based.

element.innerHTML = userInput;

Prevention: context-aware output encoding, textContent, Content-Security-Policy.

Security recommendations

  • Use parameterised queries for every database call.
  • Encode output for its context (HTML, attribute, URL, JavaScript).
  • Prefer textContent over innerHTML in JavaScript.
  • Validate input on the server — client checks are only convenience.
  • Hash passwords with a slow, salted algorithm (scrypt, bcrypt, Argon2).
  • Set HttpOnly and SameSite on session cookies.
  • Protect state-changing forms with CSRF tokens.
  • Deploy a Content-Security-Policy as defence in depth.
  • Never show raw database errors or stack traces to users.
